> 기준 문서: 유즈케이스, 화면목록, 서비스분류, 데이터설계서

**설계 요점**
- 리소스는 명사형 경로이며 `/api/v1` 아래 Next.js Route Handler로 구현한다.
- 답변 제출(`POST /answers`)은 저장 후 전사·AI 채점을 비동기로 처리하고, 클라이언트는 `GET /answers/{answerId}`의 `status`(SUBMITTED → TRANSCRIBED → SCORED / FAILED)를 폴링한다.
- 본인 데이터만 접근하며, 타인 리소스는 404로 응답한다(존재 여부 비노출, SR-002).
- 일일 AI 사용 한도 초과 시 429를 반환한다(CR-004).
- 목록은 Offset 방식 페이지네이션(`page`, `size`, 응답 `PageMeta`)을 쓴다.
- `/admin/*`은 role=ADMIN만 접근할 수 있다.

## 4. 공통 응답 코드

| HTTP 코드 | 의미 | 설명 |
|:---:|:---|:---|
| 200 | OK | 요청 성공 |
| 201 | Created | 리소스 생성 성공 |
| 202 | Accepted | 비동기 요청 접수 (재채점, 비밀번호 재설정 메일 등) |
| 204 | No Content | 삭제·로그아웃 성공 |
| 400 | Bad Request | 요청 파라미터 오류 |
| 401 | Unauthorized | 인증 토큰 없음/만료 |
| 403 | Forbidden | 권한 없음, 이메일 미인증, 음성 수집 미동의 |
| 404 | Not Found | 리소스 없음 (타인 데이터 접근 포함), 채점 완료 전 피드백 조회 |
| 409 | Conflict | 중복·상태 충돌 (이미 가입된 이메일, 이력 있는 질문 삭제 등) |
| 413 | Payload Too Large | 녹음 길이/파일 크기 초과 |
| 429 | Too Many Requests | 로그인 반복 실패, 일일 AI 사용 한도 초과 |
| 500 | Internal Server Error | 서버 내부 오류 |
